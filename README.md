# Diablo English Coach

給《Diablo Immortal》使用的精簡翻譯與語音英文教練。程式自動讀取框選的字幕／任務區：

- 主畫面只有繁中翻譯、「開啟／關閉」與「設定」
- 英文重點、A2–B1 例句與一般配裝參考用語音提供，不佔三欄畫面
- 設定可查看完整翻譯、運作狀態、配裝来源與結束程式
- 預設使用較自然的 Edge 線上神經語音，也保留 Windows 離線語音

程式不讀遊戲記憶體、不控制角色。模型只會收到已經出現在螢幕上的任務與對話；攻略更新器在啟動時另外下載固定公開來源的少量配裝欄位，不上傳遊戲文字，也不把整篇網站文章送給模型。

即時翻譯預設使用 **Ollama `qwen3.5:0.8b` 本機小模型**：不需帳號、API 金鑰或 Azure，遊戲文字不離開電腦。常見 Diablo 任務與詞句先由程式直接翻譯；其他短句才交給約 1 GB 的小模型。Azure Translator 只保留為可選備援。OCR／聊天過濾不是完整隱私防護，仍請勿把聊天區框進字幕區。

## 精簡語音版更新（2026-09-04）

### 2026-09-05 OCR、繁體與互動節奏

- OCR 保留分行與字框後才合併句子：對話區去除明確的說話者標頭；不刪除句子裡的人名或任務標題。已知英文詞的 `0/o` 混淆先修正（`y0u`、`F0ll0w`），保留百分比、數量、進度與型號；未知名稱不任意猜字。翻譯提示也要求判別殘留標頭與 OCR 錯字。
- 翻譯串流、完整譯文與快取輸出統一經 Windows NLS 轉為繁體字；保留英文名稱、數字。這是本機字體轉換，不增加推論。翻譯快取鍵更新，避免沿用 OCR 錯字版結果。
- 更新後首次啟動預設寬度至少 1200 像素（受螢幕寬度限制），重新靠近可用畫面底部；設定可選 960／1200／1400／1600。原來正值加速降為 0%，已選較慢速度則保留。之後仍可自行拖曳與調整語速。
- 一般教學在**實際播完**後預設停 12 秒，設定可選 8／12／25 秒。每三個教材位置保留一個給配裝／攻略，避免模型教材一直插隊；遊戲對話與高負載仍會延後新段落。
- 自動口說保留既有同意設定。開啟後先等 30 秒，再依 45／90／150 秒選項邀請；要求操作鍵及空白鍵安靜 8 秒、無近期對話、CPU <70%，並再穩定 3 秒。OCR 完成時也檢查邀請，避免密集 OCR 讓口說一直搶不到空檔。設定可查看等待原因。
- 跟讀與「看中文、自己用英文回答」交替。回答後提供目標句及核對回饋；仍是短句練習，不是自由聊天或發音評分。
- 趕路造成像素變動不再直接取消：改做字幕 OCR 確認。收音前也確認一次，檢出對話或無法完成檢查就跳過；口說中的檢查最多一個在途，不啟動額外模型。

### 2026-09-05 教練逐字稿

- 預設開啟「教練字幕」：實際開始播放時，在翻譯列下方顯示送去朗讀的整段文字；英文、中文、口說示範與回饋都使用同一條播放事件。排隊中、下載中或未能播放的文字不會冒充正在朗讀。
- 教練字幕最多顯示三行，長文可捲動；不覆蓋遊戲翻譯，播放結束後保留八秒再收起。這是整段逐字稿，不是逐字時間軸或卡拉 OK 高亮。
- 點擊教練字幕，或「設定 → 教練逐字稿／最近 30 段」，可選取、複製及回看本次執行的內容。僅保留在記憶體，結束程式即清空；不額外錄音、不做語音辨識、不新增模型推論。
- 「設定 → 顯示教練字幕」可關閉即時字幕，回看記錄仍可使用。

### 2026-09-05 直接、精簡的口語

- 語音不再反覆念「實際效果以遊戲為準」「不是新任務」「非最新保證」等聲明。教材用「例句」區分練習；攻略直接說候選裝備與選擇理由，来源日期留在設定中。
- 保留真正影響決策的條件，例如「拿到時」「未解鎖就先保留現有配置」；不會把未讀取的裝備當成已知資料。模型提示同步改為直接講解，具體缺資料時才簡短說明。
- 舊教練回覆快取失效；舊教材播放時只移除已知固定口頭禪，不刪除一般否定句或條件句。口說成功回饋改為核對到的結果，不每次朗讀評分限制；辨識能力說明仍保留在啟用設定。

### 2026-09-05 遊戲情境優先

- 取消多益／IC 固定輪播。先從目前任務、最近 90 秒的對話找已檢視的遊戲詞句（含變化形），先說遊戲用法，再考慮同字延伸。沒有連結時只提供遊戲英文／一般攻略，不為了湊主題插入職場或電路教材。
- 例如 `increase damage` 先解釋增加傷害，之後才可短補 `increase sales`。`cooldown` 不會被拿來硬套 IC 時序；IC 延伸目前僅開放遊戲也出現 `reset` 時的重置詞義，並區分遊戲與電路機制。
- 延伸前必須已教過同字的遊戲意思；兩次跨領域補充至少隔四則教材，同一份本機延伸不在最近十二則內重播。模型也限用該遊戲詞，並參考近期教材變換例句；這是情境選材，不是自動量測學習程度。
- 已備妥的模型教材在入列和播放前檢查關聯，畫面情境改變時丟棄不再相關的排隊教材。快取改用 `personalized-lessons-v3.json`，不讀取舊的無情境輪播教材；舊檔不刪除。
- 口說優先接續剛教過的短句；無適合句子時只使用八句遊戲相關備用題。仍保留原有遊戲對話避讓、播完一段才換下一段及負載控制。選材只使用現有 OCR 文字，不新增截圖或模型呼叫。
- 小模型的遊戲用法說明改用已檢查的本機詞義，並拒收實測發現的 cooldown／充能混淆。模型仍可變換例句和翻譯，但這些防護不代表所有生成句子都已經人工審查。

### 2026-09-05 延遲與完整教學修正

- 本機啟動器優先開啟 `publish-responsive`，舊版仍在執行時請先從設定結束它，再用啟動器開新版；不會強制關閉你的遊戲或教練。
- 翻譯改為 Ollama NDJSON 串流：第一段中文到達就顯示，標示「生成中，尚未完整」，不等整句。只有正常結束的整句會寫入快取，斷線、取消、輸出被截斷都不會把半句當完整譯文。
- 新字幕取消舊翻譯，優先取得推論資源；翻譯期間不啟動背景教學模型，也不會打斷已播放的教學段落。修正 `Ready.` 被兩單字門檻過濾而未真正預熱的問題，新預熱會略過 OCR／快取，但可被實際字幕取消。
- OCR 低負載排程 350 ms、操作中 650 ms、CPU ≥85% 仍為 2 秒；對話辨識後立即送翻譯，不再等任務區 OCR 完成。辨識後先顯示原文及本機詞義提示，明確標註這不是整句翻譯。
- **尚未保證 1 秒中文回應。** 這次舊教練仍開啟的 4-thread 小樣本，暖機後首次中文約 2.1～2.6 秒、整句約 3.9～4.7 秒；冷啟動有一次超過 12 秒而逾時。數字是從翻譯請求起算，不包含 OCR；現有 CPU 小模型仍是瓶頸。詞義提示及快取不代表所有句子已在 1 秒翻完。
- 每段教學都有「情境／目標 → 英文例句 → 整句中文 → 用法重點」，一次送成同一語音段落；生成教材缺少整句中文或用法時不播放。教材選擇與快取以以上「遊戲情境優先」規則為準。
- 2B 教材實測準備約 20～39 秒，放在背景處理，不阻擋翻譯；生成內容仍可能不自然或有錯，並非經過人工逐句審校。

串流格式依據：[Ollama 官方 Streaming 文件](https://docs.ollama.com/api/streaming)。

- 請先結束已開啟的舊教練，再執行 `啟動英文教練.cmd`；啟動器優先選 `publish-responsive`，舊的直接指向 EXE 的捷徑不會自動更新。下載包使用 `app` 目錄。
- 三條排程拆開：OCR、快速翻譯、語音教學。翻譯不等負責攻略的 2B 模型；每次只處理最新一句，舊回應不覆蓋新字幕。
- 常見任務（例如 `Head Forward and Search for Leoric`）由本機規則在 0～20 ms 左右處理，保留英文專名；其他句子交給 `qwen3.5:0.8b`。最多保存 512 句於 `%LOCALAPPDATA%/DiabloEnglishCoach/fast-translations.json`，同一句再出現通常不到 1 ms。
- 本機翻譯只連到 `127.0.0.1:11434`。啟動時在背景預熱，請求最多等 12 秒；翻譯失敗保留英文，不塞進較慢的攻略模型。Azure 模式仍使用官方端點與 Windows 認證管理員，但完全不必設定。
- 掃描第一次看到可信英文即可送翻譯，不再多等一次；可能增加 OCR 誤字風險。會过滤網址、聊天頻道標記與常見賣幣廣告；舊版過寬的下方字幕 ROI 會改為中央較小區域。不同對話版型仍可能需重新框選。
- 沒有角色字幕／疑似過場且遊戲在前景時，本機英文與攻略會在上一段講完後繼續，不再硬等 45 秒。偵測到字幕後至少等 7 秒、近期按過空白鍵至少等 5 秒；任務追蹤面板突然消失時以疑似過場處理至少 8 秒。這是 OCR／介面啟發式判斷，無法讀取遊戲內部語音狀態。
- 模型工作分成「目前任務判斷」與「背景個人化教材」。忙碌時的任務判斷維持 1 thread／至少間隔 120 秒；空閒時可在 40 秒後處理新情境，並用最多 4 threads 背景準備多益、數位 IC 面試或遊戲英文。背景生成遇到按鍵操作或高負載會取消，翻譯與本機備用教材不受影響。
- 自然語音下載超過 12 秒會嘗試離線聲音，晚到的線上語音不插播。已開始的段落仍講完；設定中要保留中文朗讀，才能聽到中文攻略／英文解說。

本機小模型資料：[Ollama `qwen3.5:0.8b`](https://ollama.com/library/qwen3.5:0.8b)。模型約 1 GB、Apache 2.0，Ollama 頁面標示支援廣泛多語言；實際遊戲品質仍由程式的 Diablo 詞彙表與本機快取輔助。

## 第一次使用

1. 雙擊 `安裝本機模型.cmd`，安裝約 2 GB 的攻略／教學模型。
2. 雙擊 `安裝本機翻譯.cmd`，安裝約 1 GB 的快速翻譯模型。兩個安裝檔都使用同一套 Ollama，不需註冊。
3. 將 Diablo Immortal 設為英文介面、英文語音、英文字幕，以及「視窗化全螢幕」。
4. 開啟遊戲後，雙擊 `啟動英文教練.cmd`。
5. 按「設定 → 辨識範圍」分別設定對話字幕區與任務目標區，再選「測試兩個辨識區」。
6. 按「開啟」。設定中的翻譯方式預設已是「本機快速翻譯」，不必處理 Azure。

只需要在第一次或遊戲解析度改變時重新框選，不需要手動截圖。

## 遊戲內長條介面

- 預設出現在遊戲畫面下方中央，避開上方中央的怪物名稱與血條；舊版儲存於上方中央的位置也會自動遷移。
- 視窗預設寬約螢幕 50%（640～1100 像素），「設定 → 翻譯列寬度」可選 740／960／1200 像素，會受螢幕寬度限制。
- 短句維持約 54 像素高，長句自動換行並最多展開四行；更長內容保留在同一翻譯區，可用右側垂直捲軸閱讀到底，不以省略號截斷。新句子會回到最上方。字型／DPI 會影響實際高度。
- 展開時盡量保持視窗下緣不動並向上增加高度，短句縮回；靠近螢幕上緣時以不超出螢幕為優先。
- 主畫面只留下翻譯、「開啟／關閉」「設定」；結束程式移入設定。
- 預設透明度為 80%；其他透明度、辨識範圍、聲音、位置與角色偏好都收在「設定」。
- 拖曳翻譯文字即可移動位置，程式會記住座標；仍可能擋到個別遊戲版型，並非自動判斷所有 HUD。
- 教練長條已排除在 OCR 擷取之外，不會把自己的翻譯當成遊戲字幕。
- 辨識框選器會固定覆蓋遊戲客戶區，不會因工作列或多螢幕縮放而突然跳位。

## 任務、英文與配裝教學

- 對話區出現新句子：自動提供簡單英文、繁中、單字與一則短英文知識。
- 任務區出現新目標：主動用「現在要做：」解釋目前行動，並教一個任務常用片語。
- 第一次任務與之後每三個新任務，会額外朗讀一則簡短流派或裝備提示；本機教材輪播也會補充配裝。
- 「設定」可選職業與「輕鬆推進／召喚流／傷害優先／生存優先」。預設依目前角色使用「死靈法師＋輕鬆推進」。
- 「設定 → 教學重點」可選遊戲為主、多益延伸偏好或數位 IC 延伸偏好；偏好只調整已有自然連結的選詞順序，不要求每類都出現。
- 配裝提示以核心技能、Damage、Life 與傳奇效果的搭配為主，不會假裝知道尚未顯示的裝備或提供容易過期的排行榜。

任務模型只接收可見文字，提示詞要求資訊不足時回答「目前畫面沒有說明」，並為常見任務指令提供固定校正。OCR 和小模型仍可能出錯，請以遊戲原文為準。配裝提示是一般練等建議，沒有掃描背包、比較兩件裝備數值或保證當季最強流派。

## 本機流派參考與啟動更新

- 目前先支援死靈法師 PvE 參考資料。其他職業沿用一般選裝原則；沒有自動判斷等級、已解鎖技能、持有裝備或進行背包 OCR。
- 每次啟動於背景檢查一個固定公開來源，最多等待 8 秒，不阻擋教練開啟，也不啟動 LLM。只抓主要攻擊、4 個技能、套裝和主副手候選；不抓劇情、掉落路線、付費推薦或整篇文章。
- 資料放在 `%LOCALAPPDATA%/DiabloEnglishCoach/guides/necromancer-pve.json`；有效更新才取代快取，另保留 `.previous` 備份。網路錯誤、驗證頁、欄位缺失或日期倒退都沿用原快取，不繞過限制或反覆重試。首次離線可用程式內建的已檢視參考資料。
- 「設定 → 本機流派資料／更新狀態」可查看來源、作者更新日期、最近成功檢查時間、錯誤訊息與候選配置。支援來源 ETag 條件請求；來源沒提供 ETag 時，下次啟動再取得該頁。
- **最近檢查時間不等於最新流派。** 目前来源作者日期是 2026-06-17，早於本次查閱；超過 30 天會標示來源較舊。即使日期很新，也不宣稱已驗證當季最強。本版尚未自動比對官方補丁或跨來源裁決配置差異。
- 來源候選不代表玩家已經擁有／需要立刻更換。前期先確認技能解鎖與實際效果；裝備名稱只作日後查閱與英文教學。
- 本機卡片直接加入空閒教學與既有配裝提示，不增加模型呼叫。原本固定配裝提示也沒有呼叫 LLM，因此此改動提升資料可查證性，而非直接縮短翻譯耗時。

來源：[Dexerto 死靈法師 PvE 建議](https://www.dexerto.com/diablo/best-diablo-immortal-necromancer-builds-1870129/)。這是來源觀點，不是官方配裝規範。

## 無對話時持續教學

- 遊戲在前景、無字幕／疑似過場且未開設定時，上一段講完並經過設定停頓才安排下一段；跳過的內容不堆積、不一次補播。
- 內建八組遊戲備用例句與情境詞句教材，並交錯最近辨識過的單字（累積至少 3 個才開始間隔複習）、本機攻略與一般配裝觀念。多益／IC 只有同字連結成立才延伸。即使模型尚未完成，也能使用本機教材。
- 偵測到角色字幕便暫緩新一段，字幕消失後仍留緩衝時間。已經開始朗讀的短段落會說完，避免再次出現每句都被切斷的問題。
- 預習的是常見句型與玩法概念，不是尚未發生的劇情、任務或裝備掉落。
- 教學不修改翻譯列，只使用語音。麥克風開啟時會暫用翻譯列顯示收音提示，結束後還原。
- 空閒 8 秒且 CPU <55% 時，2B 模型會依目前遊戲詞、最近八則教材與遇過的單字，準備含整句翻譯與用法的新教材。沒有符合的遊戲詞就不啟動這項背景工作；重複、無關聯或格式不可靠的輸出會被捨棄。本機最多保存 48 則於 `%LOCALAPPDATA%/DiabloEnglishCoach/personalized-lessons-v3.json`，不保存原始 OCR。這能依近期內容調整並減少重複，但不能宣稱已準確量出熟練度。
- 「設定 → 自動提供流派／裝備提示」只控制個別化配裝提示，關閉後仍保留遊戲英文詞彙教學。

## 自動口說（選擇啟用）

1. 重新啟動新版，按「設定 → 自動口說（空閒時）」，閱讀並同意麥克風說明；預設關閉，更新程式不會自行取得同意。
2. 按主畫面的「開啟」。首次 30 秒後尋找空檔；之後預設間隔 **90 秒**（可選 45／150），且遊戲在前景、CPU <70%、沒有正在翻譯、無近期字幕，操作鍵與空白鍵安靜至少 8 秒，再穩定 3 秒才邀請。一般教材播放时也累計安全空閒時間，於段落或 OCR 結束空檔優先邀請。設定的「口說狀態／為何尚未邀請」可查原因。
3. 優先練剛才教過、附完整中文的短句；沒有合適句子時使用八句遊戲備用題。交替「先聽英文再跟讀」與「聽中文自己用英文回答」，提示播放完並確認無對話才顯示「🎤 麥克風開啟」。不用快捷鍵；5 秒無聲跳過，有聲後安靜約 1.2 秒停止，最長 10 秒。
4. **收音期間不播放任何教材。** 麥克風關閉後立刻開始本機 Vosk 辨識；超過 1.2 秒仍未完成，且相關短補充的語音已預備好，才穿插一次。不為填空延後辨識，也不等待新的語音下載；結果很快就不插播。已開始的短句會完整講完，再接核對回饋，因此回饋可能稍等這一段，並非保證零等待。
5. 回饋核對「聽到的文字」與練習句，提示可能沒聽清的字。不是發音評分、口音評鑑或自由語音聊天；所有句子都是練習，不是新任務指令。

- 麥克風採 Windows 預設輸入，沒有系統聲音錄製或常駐喚醒詞。錄音只在記憶體、辨識後清除音訊陣列，不存檔、不上傳；示範 TTS 沿用聲音設定，線上自然聲音仍會送出**示範文字**。
- 口說期間暫停一般 OCR 掃描、LLM 與一般教學，僅保留對話安全檢查。收音後的短補充可與辨識並行，使用現成教材、不呼叫 LLM；示範期間預備語音，最多快取 8 段／4 MB 於當次記憶體。辨識模型在收音結束後才載入，完成後釋放；不回應時不載入模型。
- 每 250 ms 檢查按鍵／前景與 CPU。示範正在朗讀時，操作鍵、空白鍵、CPU ≥ 72% 或切離遊戲只標記「念完後略過收音」，不切斷示範句；如果已在收音／辨識則取消。開設定會取消收音流程，但正在播放的示範仍講完。關閉教練／退出才立即停播。錄音清理和原生辨識的一個運算區塊可能需要短暫時間，並非硬即時。
- 口說期間每秒比較原字幕區 64×16 灰階摘要，不保存圖像；明顯變動時才執行單次字幕 OCR，確認對話出現後中止。錄音前也做一次檢查。這能减少背景移動造成的取消，但字幕辨識仍可能漏判，建議戴耳機。
- 建議戴耳機；遊戲喇叭、環境噪音或其他人的聲音可能誤觸收音結束判斷／辨識。無聲與停頓目前用簡單音量門檻判斷，說話太小聲可能被略過。
- 發生裝置、權限或模型錯誤會暫停自動口說，其他教練功能仍可用。檢查 Windows 預設麥克風與「允許桌面應用程式存取麥克風」，再關閉並重新開啟教練。

### 口說模型與測試

發布資料夾包含 `speech-model/vosk-model-small-en-us-0.15`，必須與 EXE 一起保留，**不要只複製 EXE**。原始碼不包含模型；開發者先以 PowerShell 7 執行 `./安裝口說模型.ps1`，再 build/publish。腳本只下載官方固定版本，驗證 SHA-256，不開麥克風。缺檔時亦可用 `-Destination 'EXE 所在目錄/speech-model'` 安裝至指定位置。

來源：[Vosk 官方模型清單](https://alphacephei.com/vosk/models)（小型英文模型、Apache 2.0，下載約 40 MB）、[官方 C# 範例](https://github.com/alphacep/vosk-api/blob/master/csharp/demo/VoskDemo.cs)。

`--self-test self-test.json` 包含排程／取消／未同意預設／示範完成才收音等硬體隔離測試；`--speaking-test input.wav speaking-test.json` 用 16 kHz、16-bit、單聲道 PCM 檔測試實際辨識，**不開麥克風**。合成語音檔可驗證模型與發布封裝，但不代表已驗證你的口音、麥克風或遊戲 FPS。

## 聲音與速度

按主畫面的「設定 → 聲音與語速」可以選擇：

- 繁中小雨：較年輕、活潑的台灣女聲，預設使用。
- 繁中曉臻：比較溫和自然。
- 英文 Ana：較年輕的美式女聲，適合短句跟讀。
- 英文 Jenny／Aria：比較成熟、清楚。
- 語速可在 `-30%` 到 `+50%` 調整；預設為 `+18%`。
- 沒有網路時可取消「使用自然女聲」，立即改用電腦內的 Yating／Zira。

**一旦開始，會把整段念完再換下一段**：新 OCR 文字、新任務、按鍵、CPU 忙碌或開設定不搶斷當前段落。朗讀中 OCR、翻譯與下一段模型準備仍可進行；下一段語音等待目前段落結束。語音底層最多保留 3 段等待內容，過多時淘汰未播的舊內容。按「關閉」或退出才立即停播清空。

Edge 自然語音不需要 API key，但會將當前要朗讀的句子送到 Microsoft。連線失敗時會自動使用 Windows 離線語音。程式會在下載語音前與播放前各檢查一次是否出現角色字幕／疑似過場；開始播放後則把短段落說完，不反覆截斷。若遊戲對話恰好在段落開始後才出現，仍可能有很短的重疊，因為程式不讀取遊戲內部音訊事件。

## 自動負載模式

- 掃描間隔：空閒約 0.35 秒、操作中約 0.65 秒、CPU ≥85% 約 2 秒；實際 OCR 執行時間會增加等待。`Space` 視為對話，其餘鍵盤活動影響推論預算。
- 操作中只有待處理的目前任務判斷可使用 1 個推論執行緒；個人化背景生成會取消。空閒 8 秒且 CPU <55% 才用較多執行緒（最多 4 個）準備後續教材。本機教材不必等待模型。
- 鍵盤偵測不使用全域 Hook，也不保存按鍵內容，只保留「最後一次非空白鍵操作的時間」。
- Ollama 回答與一般朗讀期間不停止 OCR；自動口說收音／辨識仍會暫停掃描以節省負載。
- 新操作按鍵不取消模型；離開遊戲、開設定與關閉時仍可取消；取消 HTTP 不代表模型計算瞬間停止。
- 「關閉」停止掃描、朗讀與鍵盤輪詢，取消請求並丟棄晚到的回答。辨識測試只測 OCR，不會偷偷開啟模型或語音。
- 切換到其他程式、開設定時不開始新的背景教學，當前朗讀則講完。鍵盤判斷不等同戰鬥偵測；滑鼠戰鬥、手把或 GPU 忙碌仍可能漏判。

## 為這台筆電調整的效能配置

- 對話區依負載掃描；任務区每三輪掃描一次，不錄影、不保存畫面。
- OCR：Windows 內建模型，使用 CPU／內顯顯示路徑。
- 本機翻譯：`qwen3.5:0.8b` 強制使用 CPU，依操作與負載使用 1～4 個執行緒；模型保持載入 15 分鐘以減少反覆冷啟動。
- 攻略 LLM：`qwen3.5:2b-q4_K_M` 依每次請求負載配置 1～4 個 CPU 執行緒，保留 MX330 顯存給遊戲。它不在即時翻譯路徑上。
- Diablo Immortal：在 Windows「圖形設定」中設為高效能，交給 MX330。
- 教練視窗：已排除在螢幕擷取之外，不會讀到自己的翻譯。

Iris Xe 與 MX330 能分擔不同工作，但不能合併顯存或共同載入同一個模型。預設配置讓 MX330 專心跑遊戲，Iris Xe 負責桌面合成，CPU／16 GB RAM 跑 2B 模型。

## 沒有 Ollama 時

本機任務片語、OCR 與固定英文／配裝教材仍可用；一般句子的完整翻譯和額外情境教學需要 Ollama。若真的不想安裝 Ollama，仍可在「設定 → 翻譯方式」手動選 Azure 備援。

## 常見問題

### 找不到遊戲視窗

先啟動 Diablo Immortal，不要最小化，並使用視窗化全螢幕模式。

### 辨識出一堆介面文字

重新框選更小的字幕區，只保留畫面下方中央的對話字幕。

### 英文的 I、l 偶爾認錯

這台電腦目前只有繁中 Windows OCR；它可以讀英文，但準確度稍低。可到 Windows 的「語言與地區」加入 English (United States) 的基本輸入與光學字元辨識功能，再重新啟動教練。

### 翻譯很慢

先確認已執行 `安裝本機翻譯.cmd`。首次載入模型的實測約 4.7 秒；預熱後，本機模型的代表性短句約 0.9～1.5 秒，常見程式片語約 0～20 ms，重複快取不到 1 ms。若超過 12 秒會先保留英文，不阻塞教練。這些是本機小樣本，不代表所有遊戲句子或完整 OCR 延遲。

### 擔心爆雷

教練不保存劇情進度、不在遊戲中使用網路搜尋，也不會取得下一句。補充教材不含後續故事。

## 一般建議依據

配裝教學採技能搭配與生存／傷害取捨，不提供即時版本排行榜。背景參考：[Blizzard 裝備設計說明（早期資料，不沿用舊數值）](https://news.blizzard.com/en-us/article/23574266/itemization-in-diablo-immortal)、[Blizzard 傳奇效果範例](https://news.blizzard.com/en-us/article/24246207/sing-the-ballad-of-the-moon)。實際技能、解鎖條件與屬性仍以你遊戲內的說明為準。

## 開發與建置

Google 免費網頁自動化與 Argos 模型只做過小規模評估，未接進遊戲主流程；原因、速度與錯譯樣本見 [TRANSLATION-PILOT.md](TRANSLATION-PILOT.md)。

目前主流程預設接入本機 Ollama 小模型，Azure 僅為選用。`--translation-test translation-live.json` 會實測本機規則、小模型與快取；`--personalized-teaching-test teaching.json` 會讓 2B 模型各產生一則多益、數位 IC 與遊戲英文；`--self-test` 使用假的 HTTP 回應驗證只連 loopback、模型名稱、詞彙校正、快取，也保留 Azure 金鑰／退避測試。

測試攻略解析及快取：`--guide-test source.html guide-test.json`；實際下載一次固定來源：`--guide-refresh-test guide-refresh-test.json`。這兩種測試都不開啟麥克風或 LLM。

需要 .NET 10 SDK：

```powershell
dotnet build -c Release
dotnet publish -c Release -r win-x64 --self-contained true -o publish-readable
```
